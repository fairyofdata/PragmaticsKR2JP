# 0014. 백업: 내보내기 / 불러오기 (JSONL zip), 분석용 CSV

- 상태: 채택 (2026-10-03)

## 맥락
개인 코퍼스(`data/` 의 기록·판정·고쳐 쓰기)는 git 에서 제외되고 이 PC 에만 있다.
폴더 이름을 바꿀 때 `.env` 가 사라진 적이 있고(2026-09-21), 몇 주 쌓은 코퍼스도 같은 식으로 잃을 수 있다.
이 데이터는 사용 보고서(포트폴리오)의 원재료이기도 하다. 사용자가 "앱에 내보내기 버튼"(b안)을 골랐고, 불러오기도 요청했다.

## 결정
1. **백업 형식 = zip 안에 JSONL 그대로** (`attempts.jsonl`, `labels.jsonl`, `revisions.jsonl`) + `manifest.json`(앱 이름, 형식 번호, 내보낸 시각, 건수, 버전).
   - CSV 를 백업 형식으로 쓰지 않는 이유: 기록 한 건 안에 지적 목록·과제·판정이 **중첩**돼 있어서, 표로 펴면 되돌릴 수 없다.
     JSONL 은 앱이 원래 쓰는 형식이라 손실 없이 왕복한다.
2. **불러오기는 덮어쓰지 않고 합친다** (기록은 추가만 한다는 원칙).
   - 시도: 같은 id 가 있으면 건너뛴다. 판정·고쳐 쓰기: 완전히 같은 줄이 있으면 건너뛴다 (판정 이력은 줄마다 의미가 있다).
   - 같은 백업을 두 번 불러와도 중복이 생기지 않는다. 결과로 추가/이미 있음/읽지 못함 건수를 보여준다.
3. **"최신"은 파일의 줄 순서가 아니라 내용으로 정한다.** 합치면 옛 줄이 뒤에 붙을 수 있기 때문이다.
   - 판정: 기록된 시각이 가장 늦은 것 (`store.load_labels`).
   - 고쳐 쓰기: 같은 id 면 다시 채점한 쪽 (`store.load_revisions`).
4. **분석용 CSV 는 내보내기 전용**: 확정 지적 한 건 = 한 줄, 21열 (원문, 지적, 판정, 패턴, 변환 실수 후보 등). UTF-8 BOM 을 붙여 엑셀에서 한국어·일본어가 깨지지 않게 한다.
   원어민 검수를 맡길 때 이 파일을 그대로 쓴다.
5. 위치: 사이드바 "백업 · 내보내기 / 불러오기". 내려받기 데이터는 버튼을 누를 때만 만든다.

## 안전
- 불러오기는 zip 을 디스크에 풀지 않는다. 정해진 세 파일과 manifest 만 메모리에서 읽고, 다른 이름(`../evil.txt` 등)은 무시한다.
- manifest 가 없거나 다른 앱의 것이면 거부. 압축을 풀었을 때 50MB 를 넘으면 거부. 거부한 파일은 아무것도 쓰지 않는다.
- JSON 이 아닌 줄, 필수 필드가 없는 시도는 건너뛰고 건수로 알린다.

## 버린 대안
- 비공개 GitHub 저장소에 `data/` 올리기: 이력이 남지만 PII 게이트 이전에는 부담.
- 동기화 폴더로 `data/` 옮기기: `COACH_DATA_FILE` 로 지금도 가능. 사용자가 원하면 병행할 수 있다.
- 덮어쓰기 복원: 실수로 최근 기록을 잃을 수 있어 넣지 않았다.

## 한계
- 백업은 사용자가 직접 눌러야 한다 (자동 백업 없음).
- 백업 파일은 암호화하지 않는다. 사용자가 쓴 글이 그대로 들어 있으니 보관 위치는 사용자가 정한다.
- 시연용 예시(`samples/`)는 백업에 넣지 않는다 (git 에 있다).
