# 0016. CI(테스트만), 폰 화면 정리, 같은 망에서 폰 접속

- 상태: 채택 (2026-10-03). ADR 0015 의 "제안하는 순서" 1단계를 사용자가 승인.

## 맥락
지금 구조: 별도 백엔드 없음. `streamlit run` 으로 띄운 파이썬 프로세스 하나가 화면, OpenAI 호출, 파일 저장을 모두 한다.
모바일은 최초 기획("실제로 쓴 일본어는 회사와 이동 중에 생긴다")과 맞지만, Firebase 배포는 선행 조건(실사용 확인, PII 게이트, 인증·저장·예산)이 남아 있다 (ADR 0015).
그래서 배포 없이 모바일로 쓸 수 있는 가장 짧은 길을 먼저 간다.

## 결정
1. **CI = 테스트만.** GitHub Actions 가 push·PR 마다 `pytest` 를 돌린다 (`.github/workflows/tests.yml`). 배포는 없다.
   테스트는 LLM 을 부르지 않아서 비밀 값(API 키)이 필요 없다. 권한은 읽기 전용.
   화면 자체도 검사한다 (`tests/test_app.py`, Streamlit AppTest): 모든 모드·입력 방식이 오류 없이 뜨는지, 요약이 보이는지.
2. **폰 화면 정리.** 폰에서는 사이드바가 접힌다. 매번 쓰는 것(모드, 주제)을 본문으로 옮기고, 사이드바에는 요약 설정과 백업만 둔다.
   모드 이름은 짧게("문법 (정확성)" / "표현 (적절성)"), 요약의 숫자 세 개는 가로 한 줄 (`st.container(horizontal=True)`; `st.columns` 는 폰에서 세로로 쌓인다).
3. **같은 망에서 폰 접속.** `python -m tools.run_mobile` 이 앱을 사설망에 열고 접속 주소를 알려 준다. 내 PC 가 서버다.

## 구현 중 발견한 것 (보안)
**Streamlit 은 주소를 지정하지 않으면 모든 네트워크에 열린다.** 즉 지금까지도 `streamlit run app.py` 만 하면
같은 Wi-Fi 의 다른 기기가 접속해서 내 기록을 보고 내 API 키로 채점을 돌릴 수 있었다 (방화벽이 허용했다면).
- `.streamlit/config.toml` 에서 기본 주소를 `localhost` 로 고정했다. 기본 실행은 이 PC 에서만 접속된다.
- 네트워크에 여는 길은 `tools.run_mobile` 하나뿐이고, **`.env` 에 `COACH_PASSCODE`(8자 이상)가 없으면 실행을 거부한다.**
- 앱은 `COACH_PASSCODE` 가 설정돼 있으면 암호를 맞게 넣기 전에는 아무것도 보여주지 않는다 (`require_passcode`, 시간차 공격을 피하는 비교).

## 버린 대안
- Firebase/Cloud Run 배포: 로그인·저장소 이전·PII·예산이 한꺼번에 필요하다. 실사용 후 재검토 (ADR 0015).
- 암호 없이 사설망에 열기: 집 Wi-Fi 라도 손님 기기·IoT 기기가 같은 망에 있다.
- 화면을 웹앱(PWA)으로 다시 만들기: 별도 프로젝트 규모다.

## 한계
- 암호는 한 개를 공유하는 단순 잠금이다. 통신은 암호화되지 않는다(http) → **집이나 사설망(Tailscale 등)에서만**, 회사·공용 Wi-Fi 에서는 쓰지 않는다.
- PC 가 켜져 있고 앱이 떠 있어야 폰에서 쓸 수 있다.
- 방화벽 허용은 사용자가 직접 한다 ("개인 네트워크"만).
- 연습 화면 스크린샷(`practice.png`)은 API 가 필요해서 이번에 다시 찍지 않았다. 요약·폰 화면만 새로 찍었다.
