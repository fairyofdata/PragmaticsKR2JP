# 0003. 고정 few-shot 없이 코드북, 흔들림은 3회 다수결

- 상태: 채택 (2026-09-20)

## 맥락
- 답 전체를 보여주는 고정 few-shot 예시는 주제·오류 유형을 예시 쪽으로 쏠리게 할 위험이 있다(사용자 지적).
- 문법 교정(GEC) 연구: LLM은 기본적으로 과교정한다. few-shot은 도움이 되지만 효과 있는 예시는 "입력과 같은 오류 패턴"이고, 고정 예시가 아니라 검색해서 고르는 방식이 연구되고 있다.
- 같은 입력을 여러 번 생성해 수정 단위로 다수결하면 과교정이 줄고 프롬프트 변화에 덜 흔들린다는 보고.
- Gemini 3 공식 문서는 temperature 1.0 유지를 강하게 권장, OpenAI 추론 모델은 temperature 를 지원하지 않는다 → temperature 0 으로 흔들림을 누르는 방법은 쓸 수 없다.

## 결정
- 프롬프트는 **상세 지침(코드북)**: 유형마다 정의, 경계 규칙, 과제와 무관한 짧은 대비쌍 1개씩, 모든 유형에 균등. "오류 없음"도 정상 결과라고 명시.
- 같은 답을 **3회 채점**, 같은 유형이고 위치가 겹치는 지적이 2회 이상이면 확정, 1회면 "참고(낮은 확신)". 합치는 것은 코드.
- 평가 세트 문장과 프롬프트 대비쌍은 겹치지 않게 한다(누수 방지).

## 결과
- 실험: 상세 지침이 단순 지시보다 확실히 낫다. p1 한 실행 안에서 유형 일치 0.49 → 0.71, 기대 밖 태그 0.70 → 0.10, 무오류 답의 태그 1.17 → 0.33 (p0 도 같은 방향).
- 다수결의 효과는 문항 12개로는 판단 불가. 태그별 확신도("3번 중 몇 번")를 주므로 기본값 유지. 비용 3배(채점 1번 약 $0.02).
- 위반 발견: p1 에 넣은 "(예: 조사와 바로 뒤 동사의 한자)" 문구가 평가 문항 G1 모양 그대로다 → p2 에서 일반 문장으로 교체 예정.
- 다음 단계: 기록이 쌓이면 같은 유형의 과거 사례를 검색해 넣는 동적 few-shot.
