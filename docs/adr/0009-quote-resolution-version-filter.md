# 0009. 인용 위치 결정, 버전 필터, 확정 태그 교정문 (외부 리뷰 반영)

- 상태: 채택 (2026-09-21). 0002 의 검증 D·E 구현을 보강.

## 맥락 (외부 리뷰에서 받은 지적)
1. **[버그] 인용 위치.** `find_span` 이 첫 등장 위치만 썼다. 같은 문자열(특히 조사 「を」)이 답에 여러 번 나오면
   서로 다른 오류 두 건이 같은 위치로 해석돼 다수결에서 한 지적으로 합쳐지고 하나가 사라졌다.
   재현: `友達を会って、映画を見るを好きです。` 에서 を→に, を→のが 두 태그 → 확정 1건.
   같은 원인이 **누락 검증 E 도 뚫고 있었다**: 「を」 태그 하나가 답 안의 모든 「を」를 덮은 것으로 처리돼, 다른 「を」의 조용한 수정이 드러나지 않았다.
2. **[원칙-구현 불일치]** README 는 "유형표·프롬프트·스키마·모델 버전이 다르면 섞지 않는다"인데, 코드는 모드와 유형표만 걸렀다.
3. **[표시]** 화면 교정문(3회 중 한 샘플)과 오류 목록(다수결 결과)의 출처가 달라, 확정되지 않은 수정이 교정문에 섞일 수 있었다.

## 결정 (사용자 선택)
1. **(a)+(b)+(c) 모두.**
   - (a) 태그에 `context_before` / `context_after`(인용 바로 앞뒤 2~4자) 필드 추가. 프롬프트 p2.
   - (b) 코드가 위치를 정한다 (`verify.resolve_span`): 후보 = 모든 출현 위치 → 문맥이 맞는 것 → 같은 샘플의 다른 태그가 가져가지 않은 것
     → 그 샘플 교정문에서 실제로 바뀐 곳과 겹치는 것 → 바뀐 내용이 태그의 corrected 와 같은 것. 어느 단계에서 후보가 0이 되면 그 단계는 건너뛴다.
     (a)만 믿지 않는 이유: 지난 실험에서 모델이 프롬프트 규칙을 안정적으로 따르지 않았다.
   - (c) 그래도 하나로 못 정하면 첫 후보를 쓰고 `ambiguous_quotes` 로 세어 화면에 경고.
   - 누락 검증 E 는 "모든 출현"이 아니라 **정해진 위치만** 덮은 것으로 본다.
2. **기본 엄격 + 선택 토글.** 기본은 네 버전이 모두 현재와 같은 기록만 집계. 사이드바 토글을 켜면 유형표만 같은 기록을 포함하고,
   섞인 (프롬프트·스키마·모델) 구성을 화면에 경고로 보여준다. 유형표가 다르면 어느 경우에도 섞지 않는다.
3. **확정 태그로 코드가 교정문을 만든다** (`verify.apply_tags`). 오류 목록과 교정문이 항상 일치한다.
   한 태그가 다른 태그를 감싸고 안쪽 교정이 바깥 교정에 포함되면 바깥만 적용. 그 밖의 겹침은 충돌로 보고 샘플 교정문으로 대신하며 그 사실을 표시.
   누락 검증 E 는 여전히 샘플 교정문(LLM 이 실제로 고친 것)을 기준으로 한다.

함께 한 것: p2 에서 평가 문항 G1 모양의 예시 문구("조사와 바로 뒤 동사의 한자")를 뺐다 (0003 에서 예고한 누수 제거).
요약 화면의 상위 5개 옆에 신뢰도(확정 건수, 전원 일치 건수, 평균 일치율, 낮은 확신 건수)를 붙였다.

## 결과
- 버전: 프롬프트 p1→p2, 스키마 s1→s2 (`context_before/after`, `ambiguous_quotes`, `confirmed_correction`, `correction_source`).
- 테스트: 리뷰의 재현 케이스를 먼저 실패하는 테스트로 넣고 고침. 문맥 선택, 모호 표시, 교정문 생성·충돌, 버전 필터 테스트 추가 (총 23개).
- 기존 시연 예시(p1·s1)는 기본 설정에서 집계되지 않는다 → 재생성 필요. 실험도 p2 로 다시 돌려 README 를 갱신한다.
