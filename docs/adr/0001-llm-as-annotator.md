# 0001. LLM은 주석자, 측정의 나머지는 코드

- 상태: 채택 (2026-09-20)

## 맥락
최초 원칙은 "LLM에게 측정을 맡기지 않는다"였다. 검수해 보니 이 프로젝트에서는 문구 그대로 지킬 수 없다.
"이 문장이 부자연스러운가"를 판정할 LLM 밖의 도구가 사실상 없어서(규칙 기반 검사기는 표기·일부 문법만),
오류 태그 하나하나가 이미 LLM의 측정이다. 문구 그대로 두면 "코드로 집계했으니 객관적"이라는 착각을 낳는다.

## 결정
- LLM은 **고정 유형표 아래의 항목 단위 주석자**다: 출제, 오류 위치·유형 태깅, 교정문, 해설.
- LLM에게 맡기지 않는 것: 점수, 수준 판정, 누적·순위·추세, 자기 결과의 검증.
- 코드가 하는 것: 인용 검증, 미태깅 수정 검출, 다수결, 집계, **주석의 신뢰도(재현성)와 타당도(탐지율) 측정**.
- 버전(유형표·프롬프트·스키마·모델)이 다른 기록은 섞어 집계하지 않는다.

## 근거
- LLM 판정자의 수치 점수는 잡음이 크고, 구체적 범주 판단이 더 안정적이라는 보고.
- L2 작문 피드백 연구: LLM은 표면 교정에 강하고 화용(독자 인식·관습)에 약하다. 타당도는 기술의 성질이 아니라 용도·조건에 달렸고, 근거가 지지하는 범위는 사람이 감독하는 형성 평가(개인 학습)다.

## 버린 대안
- LLM에게 총점·레벨을 매기게 하기: 재현성·보정 문제.
- 규칙 기반 검사기만 쓰기: 화용·뉘앙스를 못 다룬다.
