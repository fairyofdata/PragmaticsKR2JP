# 0017. 세션 인수인계 문서와 SessionStart 훅

- 상태: 채택 (2026-10-07)

## 맥락
이 프로젝트는 여러 세션에 걸쳐 진행된다. 세션이 바뀌면 대화 내용은 사라지고, 새 세션은 `CLAUDE.md` 와 ADR 만 본다.
그 둘에는 원칙·구조·결정의 이유는 있지만, **"지금 어디서 멈췄나"와 문서로 남지 않은 것**(답을 기다리는 질문, 확인하지 못한 것,
이 환경에서 걸렸던 함정, 사용자와 일하는 방식)이 없다. 사용자가 새 세션으로 넘어갈 수 있게 인수인계를 요청했다.

## 결정
1. **`docs/HANDOFF.md`** 에 인수인계를 둔다. `CLAUDE.md`·ADR 과 겹치지 않게 다음만 적는다:
   지금 멈춘 지점과 새 세션의 첫 행동, 저장소 상태, 보류 목록, 사용자가 직접 해야 하는 것과 미확인 항목, 사용자와 일하는 방식, 환경에서 걸렸던 것.
2. **SessionStart 훅**이 새 세션 시작 시 이 문서를 세션 문맥에 넣는다 (`tools/session_handoff.py`).
   - 문서 전문에 **그 시점의 git 상태**(마지막 커밋, 커밋 안 된 변경, 푸시 안 된 커밋)를 붙인다. 문서가 낡았는지 새 세션이 알 수 있다.
   - 표준 라이브러리만 쓴다 (가상환경 없이 시스템 파이썬으로 돈다). 출력은 UTF-8 바이트로 직접 쓴다 (Windows 콘솔 인코딩으로 한국어가 깨지지 않게).
   - 어떤 이유로든 실패하면 조용히 끝난다. 훅 때문에 세션 시작이 막히면 안 된다.
3. 훅 등록은 **`.claude/settings.local.json`** (이 PC 전용, git 제외). 스크립트와 문서는 커밋한다.
   다른 PC 에서 쓰려면 같은 설정 파일을 만들면 된다 (아래).
4. **세션을 끝내기 전에 `docs/HANDOFF.md` 를 갱신한다** (CLAUDE.md 에 규칙으로 추가).

## 버린 대안
- `CLAUDE.md` 에 다 넣기: 이미 길고, 원칙(오래 가는 것)과 진행 상태(자주 바뀌는 것)가 섞인다.
- 기억(memory) 기능에만 의존: 저장소와 함께 버전 관리되지 않고, 사용자가 읽고 고치기 어렵다.
- 설정을 `.claude/settings.json` 으로 커밋: 공개 저장소를 받은 사람의 세션에서도 훅이 돈다. 개인 작업 흐름이라 로컬에 둔다.

## 한계
- 훅은 문서를 넣어 줄 뿐이다. 문서를 갱신하지 않으면 낡은 내용이 들어간다 → git 상태를 함께 붙여 어긋남을 드러낸다.
- 설정 파일이 git 에 없으므로, 폴더를 새로 받으면 훅을 다시 등록해야 한다:

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command", "shell": "bash",
          "command": "python \"${CLAUDE_PROJECT_DIR:-.}/tools/session_handoff.py\" 2>/dev/null || true",
          "timeout": 20 } ] }
    ]
  }
}
```
