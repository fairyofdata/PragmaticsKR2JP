# 0021. 공개 저장소에서 개인·로컬 서술을 분리한다

- 상태: 채택 (2026-10-31)

## 맥락
이 저장소는 공개이고, 포트폴리오로 링크된다. 그런데 에이전트용 문서에 공개할 이유가 없는 것이 섞여 있었다.
- `CLAUDE.md` 의 사용자 절(프로필, 코딩에 대한 자기 평가)과 로컬 경로.
- `docs/HANDOFF.md` 전체: 세션 사이의 대화 요지, 사용자 발언 인용, 일하는 방식, 로컬 파일 이름.
- 다른 곳에서 가져오는 자료의 출처 쪽 사정 (ADR 0020 의 원래 판).

## 결정
1. 사용자 프로필·일하는 방식·열지 않을 경로는 `CLAUDE.local.md` 로 옮긴다 (git 제외. Claude Code 가 CLAUDE.md 와 함께 읽는다).
2. `docs/HANDOFF.md` 는 git 에서 뺀다. 경로와 SessionStart 훅은 그대로라 이 PC 의 세션은 전과 같이 읽는다. 훅은 파일이 없으면 안내만 하고 넘어간다 (ADR 0017).
3. 출처 쪽 사정이 적힌 메모·지시문은 `private/` (git 제외, ADR 0020).
4. 공개 문서(README·ADR·CLAUDE.md)에는 설계·결정·측정만 쓴다. 사용자 개인 사정·직장 쪽 사정·로컬 경로는 쓰지 않는다.
5. HANDOFF 를 읽는 테스트는 임시 문서를 쓴다 (CI 에는 HANDOFF 가 없다).

## 버린 대안
- 저장소를 비공개로: 포트폴리오로 쓰므로 안 된다.
- 비공개 짝 저장소로 나누기: 앱 실행에 필요한 자료가 아니고 양도 적다. 비공개 저장소라도 밖의 서비스에 올리는 것이다.
- HANDOFF 를 일반화해서 공개로 남기기: 인수인계의 쓸모는 구체성에 있어서, 일반화하면 둘 다 잃는다.

## 알려진 한계
- 이미 공개된 이전 커밋에는 옛 CLAUDE.md·HANDOFF 가 남아 있다. 지우려면 이력을 다시 써야 한다 (강제 푸시, 사용자 결정).
- 클라우드 세션(저장소를 내려받아 쓰는 세션)은 HANDOFF 를 볼 수 없다. CLAUDE.md 의 '현재 상태와 다음 할 일'로 이어 간다.
- 로컬 전용 파일은 git 에 없어 백업이 따로 필요하다.
