# 0019. 실제로 쓴 일본어 입력, 상대가 바뀌면 어떻게, PII 게이트 연계 보류

- 상태: 채택 (2026-10-07). ADR 0015 의 2단계. 배포 방식은 아직 정하지 않았다 (아래 "정하지 않은 것").

## 맥락
사용자가 "실사용하기엔 원하는 기능이 덜 갖춰졌다"고 했고(2026-10-03), 무엇이 부족한지 물었다. 답 (2026-10-07):
- 실제로 쓴 일본어 넣기, 상대가 바뀌면 어떻게, 폰에서 편하게 쓰기(클라우드 배포), 해설의 질 — 네 가지 모두.
- 다만 해설의 질은 "아직 실사용을 안 해서 모른다"고 했다.
- 다른 곳에서 가져오는 글은 가져오기 전에 그쪽에서 개인·업무 정보를 가리고 일반화한다. 그래서 이 앱에서 PII 를 다룰 필요가 없다.

## 결정
1. **PII 게이트 연계는 무기한 보류.** 이 앱에 들어오는 글은 이미 가려진 글이다. '원문은 로컬, 채점은 가린 문장 기준' 규칙도 만들지 않는다.
2. **입력 방식 `own_japanese` (실제로 쓴 일본어).** 일본어를 붙여 넣고 매체·상대, 선택으로 한국어 한 줄 상황을 적으면 바로 채점한다.
   - 채점 프롬프트는 그대로다 (`PROMPT_VERSION` p2 유지). 과제 자리에 "과제의 답이 아니라 실제로 쓴 글"이라는 사실만 넣는다 (`llm.own_japanese_task`, LLM 호출 없음).
   - 원문은 붙여 넣은 그대로 저장한다 (원칙 2-A). 걸린 시간은 없다 (`duration_sec=None`).
   - **집계에 넣는다** (사용자 결정). 가장 실제에 가까운 기록이기 때문이다. 다만 사전을 썼을 수 있어 연습과 조건이 다르므로,
     요약 탭에 입력 방식 구성(`stats.input_mix`)을 보여준다. 걸린 시간 중앙값에는 원래 들어가지 않는다 (시간이 없는 기록은 빠진다).
   - 스키마 s4 → s5 (입력 방식 값 추가. 버전 필터에는 영향 없음, ADR 0012).
3. **상대가 바뀌면 어떻게 (`llm.register_contrast`).** 채점 결과 아래의 버튼으로 시작한다 (사용자 결정: 독립 탭이 아니라 내 글에 붙인다).
   - 방금 쓴 글의 뜻(`intended_meaning_ko`)과 자연스러운 문장을 주고, 같은 뜻을 사외 거래처 / 사내 상사 / 사내 동료 / 친한 친구에게 각각 쓰게 한다. 매체는 그대로.
   - 상대 목록은 코드가 정한다 (`prompts.CONTRAST_RELATIONSHIPS`). 모델이 돌려준 상대 이름은 쓰지 않는다.
   - **인용 검증을 그대로 적용한다** (`verify.check_contrast`): 모델이 "이 상대에게는 이 표현"이라고 짚은 것이 그 문장에 글자 그대로 없으면 그 설명을 버린다.
     모든 상대에서 표현이 같은 설명(차이가 아님)도 버린다. 버린 건수는 화면에 보여준다.
   - 측정이 아니다: 1회 호출, 다수결 없음, 집계 제외, 저장하지 않음 (새 과제를 시작하면 사라진다). 화면에 "1회 쓴 것이라 참고로만"이라고 적는다.
   - 채점 프롬프트와 별개라 `PROMPT_VERSION` 은 올리지 않는다.
4. **해설의 질은 만들지 않는다.** 써 보기 전이라 무엇이 부족한지 모른다. 실사용 뒤에 다시 묻는다.

## 측정을 오염시키나 (원칙 6)
- `own_japanese`: 유도한 오류가 아니므로 `targeted` 처럼 뺄 이유는 없다. 다만 사전·번역기를 썼을 수 있어 오류가 적게 나오는 방향으로 다르다 → 구성 표시로 드러낸다.
- 상대 대비: 채점 뒤에 보는 설명이고 기록에 남지 않는다 → 집계에 영향 없음.

## 알려진 한계 / 확인하지 못한 것
- **두 기능 모두 실제 API 로 돌려 보지 않았다.** 테스트는 가짜 응답으로만 했다 (58개 통과). 상대 대비의 비용(약 $0.01~0.02)은 추정이다.
- 가져오는 쪽에서 가릴 때 일본어 오류까지 고쳐지면 약점이 기록되지 않는다. 가리는 지시에 "언어 오류는 그대로 둘 것"이 있는지 사용자가 확인해야 한다.
- 마스킹 자리표시(`[会社名]` 같은 것)를 채점이 오류로 잡을 수 있다. 자리표시의 모양을 알게 되면 코드로 거른다 (프롬프트 규칙으로 넣지 않는다, 원칙 2의 교훈).
- 상대 대비의 문장은 모델이 쓴 것이고 원어민 검수가 없다. 코드가 확인하는 것은 인용이 실제로 있는지뿐이다.
- 상대 대비는 채점 1회분의 `natural_version` 을 참고로 준다. 그 문장이 어색하면 대비도 영향을 받는다.

## 버린 대안
- 실제 글을 집계에서 따로 떼기: 조건은 깨끗하지만 실제 글에서 반복되는 오류가 빈출 오답에 오르지 않는다. 최초 기획과 반대 방향이다.
- 상대 대비를 독립 탭으로: 사전처럼 쓰게 되고 내 글과 연결이 끊긴다. 필요해지면 같은 함수로 추가할 수 있다.
- 상대 대비를 저장: 백업 형식이 늘어난다. 다시 보고 싶다는 필요가 실제로 생기면 한다.
- 채점 프롬프트에 대비 설명을 함께 요청: 측정 도구가 바뀌어 p2 실험을 다시 돌려야 한다.

## 정하지 않은 것: 배포
사용자는 클라우드 배포를 원한다. PII 가 선행 조건에서 빠졌으므로 남은 것은 저장·인증·예산이다.
제안: Streamlit Community Cloud(화면) + Firestore(기록 저장) + 기존 암호 잠금 + OpenAI 월 한도. 사용자 답을 기다린다 (`docs/HANDOFF.md`).
- Firebase Hosting 만으로는 안 된다: 정적 파일만 올릴 수 있고 이 앱은 파이썬 서버가 필요하다.
- 클라우드에서는 파일 저장이 유지되지 않는다 → `coach/store.py` 를 외부 저장소로 바꾸는 작업이 핵심이다.
