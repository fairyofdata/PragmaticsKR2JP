# 0020. 외부 교정 기록의 가져오기 형식: 오답 노트가 아니라 문장 쌍(JSONL)

- 상태: 제안 (2026-10-07). 형식과 지시문만 정했다. 앱의 불러오기 기능은 아직 없다.

## 맥락
ADR 0019 에서 '실제로 쓴 일본어' 입력을 만들 때 "밖에서 가져오는 글은 가려진 원문으로 온다"고 가정했다. **이 가정이 틀렸다.**
사용자가 실제 예시를 보여 줬다: 다른 도구가 이미 채점·분류·해설한 **오답 노트**가 온다.
- 문장이 아니라 조각이라 인용 검증을 할 수 없다.
- 판정한 도구가 다르고(다른 모델, 1회), 오류 없는 문장이 없어 분모가 없다.
- 붙여 넣으면 표가 풀려서 코드로 읽기 불안정하다.

사용자 요청: 이 앱이 필요로 하는 입력 형태를, 내보내는 쪽 모델이 일반화해서 내보낼 수 있는 지시문으로 제안할 것.

## 결정
1. 노트의 형식(추론으로 복원)과 내보내는 쪽 지시문은 이 PC 의 `private/` 에만 둔다 (git 제외). 출처 쪽 사정이 적혀 있어 공개 저장소에 올리지 않는다. 노트 내용은 저장하지 않는다.
2. 이 앱이 받을 형식 `kr2jp-export` v1 을 정한다: 코드 블록 하나에 JSON Lines.
   머리줄(문서 종류·매체·상대·문장 수·제외 수) + 문장마다 `draft`(틀린 채로 일반화한 초안) / `reviewed`(검토본) / `reviewed_by` / `changed`.
3. **내보내는 쪽 모델에게 분류·해설을 시키지 않는다.** 채점은 이 앱의 측정 도구가 한다 (원칙 1: 도구가 다른 기록을 섞지 않는다).
4. **오류 없는 문장도 받는다.** 분모와 과교정 측정을 위해서다.
5. 사람이 고친 검토본(`human`, `team_final`)은 이 앱 채점의 정답지로 쓸 수 있다 → 탐지율 측정의 재료 (ADR 0007 의 평가 세트를 실제 글로 만드는 길).
   모델이 고친 것(`model`)은 정답지로 쓰지 않는다.

## 버린 대안
- 오답 노트를 코드로 파싱: 표 모양이 장마다 다르고 구분자가 예문 안에도 나온다.
- 오답 노트를 LLM 으로 읽기: 읽으면서 내용을 고쳐 읽을 수 있고, 그래도 조각이라 검증할 수 없다.
- 내보내는 쪽에서 유형표(v1)로 태깅까지 해서 받기: 편하지만 다른 도구의 판정이 집계에 들어온다.
- 오류 쌍만 한 줄 형식으로 받기 (직전 턴의 제안): 겨냥 연습 재료로는 충분하지만 분모와 정답지를 얻지 못한다. 문장 쌍이 있으면 오류 쌍은 diff 로 얻을 수 있다.

## 알려진 한계
- 일반화 과정에서 오류가 고쳐질 위험은 지시문으로만 막고 있다. 이 앱에서는 확인할 수 없다 (원문이 없다).
- 지시문은 보안을 보장하지 않는다. 내보낼지는 출처 쪽 규칙과 사용자의 판단이다.
- 지시문을 실제로 돌려 본 적이 없다. 내보내는 쪽 모델이 형식을 지키는지 모른다.
