# 0007. 평가 세트를 사용자의 실제 번역에서 만든다

- 상태: 제안 (진행 중, 2026-09-20)

## 맥락
현재 평가 세트 12건은 Claude 가 상상한 "전형적 실수"다. 사용자의 예시 하나(`友達を合う`)에 설계가 끌려간 흔적도 있다
(평가 문항 G1, p1 프롬프트 예시 문구, E2 규칙이 모두 같은 모양). 실험에서 정답 라벨 오류도 1건 발견됐다.
이 앱이 잡아야 할 대상은 "한국어 화자 일반"이 아니라 사용자 본인의 오류이고, 오타인지 오개념인지는 본인만 판정할 수 있다.

## 결정
1. 사용자가 한국어 글을 사전·번역기 없이 일본어로 번역해 가져온다. 글 종류를 섞는다:
   매체(書き言葉/메일/채팅/구두) × 관계(불특정/사외/윗사람/동료/친구) × 기능(부탁·사과·거절·보고·의견·감사·설명·경험 서술).
   후보 8종: 친구 메신저, 동료 채팅, 상사 메일, 사외 문의 메일, 회의 발언, 일기·에세이, 절차 설명, 수수표현 이야기.
2. 1차 4편 → 유형별 건수를 코드로 세고 → 0건인 유형을 겨냥해 2차 글을 고른다.
3. **앱을 돌리기 전에** Claude 가 독립적으로 분류한다(앱 채점 모델과 다른 모델). 앱 결과로 정답을 만들면 순환이다.
4. 사용자와 상의해 오류마다 `origin: typo / misconception / unsure` 를 사용자가 판정. 확신이 낮은 것은 지표에서 빼고 나중에 원어민에게 확인.
5. 오타도 버리지 않는다(끌려가지 않기 탐지 재료). 탐지율을 오개념/오타로 나눠 보고. 오개념만 모아 시연 샘플(`source: "imported"`)도 만든다.
6. 오류 없는 문장도 평가 세트에 넣는다(과교정 측정, 목표 30% 이상).

## 주의
- 한국어 원문은 되도록 남이 쓴 실제 글에서 (직접 쓰면 옮기기 쉬운 한국어를 고르는 회피가 생긴다).
- 번역 과제는 자유 작문보다 직역 간섭이 많이 나온다 → README 에 밝힌다.
- 기사·드라마 대사 원문은 저작권 때문에 요지만 살려 다시 쓰거나 `data/`(git 제외)에 둔다.
- 사용자 확인: 회사 내용 없음, 일반 회화 → git 커밋 가능.
