# 0008. 범용 검증 층과 일본어 층을 분리

- 상태: 채택 (2026-09-20). 0002 의 E2·전각반각 규칙을 대체.

## 맥락
코드의 규칙을 점검해 보니 두 가지 문제가 있었다.
1. **합침 검출(E2)이 사례 하나에 맞춰져 있었다.** 조건이 "수정이 2개 이상이고 그중 하나가 한자→한자"였는데,
   이 한자 조건은 `を合→に会` 를 잡기 위한 것이었다. `駅を書けた→駅に書いた`(한자가 안 바뀜)는 그대로 빠져나갔다.
2. **전각/반각 필터가 너무 넓었다.** NFKC 로 통째로 비교해서 `ｻｰﾊﾞｰ→サーバー`, `㈱→(株)` 까지 "차이 없음"으로 처리했다.
   과교정을 막으려던 규칙이 진짜 표기 오류를 지우고 있었다 — 끌려가지 않기 원칙에 정면으로 어긋난다.

또 범용 규칙(인용 검증, 커버리지, 다수결, 집계)과 일본어 지식(가나·한자 범위, 단어 나누기)이 한 파일에 섞여 있었다.

## 결정
- `coach/lang_ja.py` 를 만들고 일본어 지식을 전부 옮긴다. 밖으로 내보내는 것은 두 함수뿐:
  `tokenize_chunks(text)`, `non_error_diff(a, b)`. `coach/verify.py` 는 언어를 모른다.
- **합침 검출을 일반화**: "태그 하나 안에서 서로 다른 **단어**가 2개 이상 고쳐졌으면 경고". 한자 조건 삭제.
- **단어 나누기는 SudachiPy**(형태소 분석). 없으면 기존 표기 기반 근사로 자동 대체(`TOKENIZER` 로 확인 가능).
  문절에 가깝게 묶는다: 조사·조동사·접미사는 앞말에 붙이고, 非自立可能 동사는 명사 뒤(`連絡+する`)나 て/で 뒤(`〜てあげる`)에서만 붙인다.
  (`合う` 는 사전에서 非自立可能 이라, 이 단서가 없으면 `友達を` 에 붙어 검출을 놓친다)
- **전각/반각 규칙을 좁힌다**: 한 글자가 한 글자 ASCII 로 바뀌는 경우(문장부호·공백·숫자·영문)만 오류가 아닌 것으로 본다.
  반각 가타카나와 `㈱` 같은 합자는 표기 오류로 남긴다.

## 결과
- 검증 대상 사례 10개로 확인 (테스트에 포함). `友達を合って→友達に会って`, `駅を書けた→駅に書いた` 는 경고,
  `薬を食べて→薬を飲んで`(한 단어 안의 활용), `連絡しました→ご連絡いたしました`(경어 삽입)는 경고 없음.
- 의존성 추가: `sudachipy`, `sudachidict_core` (사전 포함 약 70MB). 없어도 동작한다.
- **README 의 실험 표는 이 변경 이전 숫자다.** 당시 결과 파일에는 모델의 원래 응답이 없어 다시 계산할 수 없다
  (원래 응답 저장은 그 뒤에 추가했다). 다음 실험부터는 `--rescore` 로 API 없이 다시 잴 수 있다.
- 다른 언어로 확장할 때는 같은 두 함수를 가진 `lang_xx.py` 를 추가하면 된다.
