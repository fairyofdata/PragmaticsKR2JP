# 0015. 방향 점검: 최초 기획과의 정렬, 모바일 UI·Firebase 배포 검토

- 상태: 검토 (2026-10-03). 결정 대기 — 아래 "제안하는 순서"에 대한 사용자 선택이 필요하다.

## 최초 기획 (사용자의 말)
일본에서 회사 생활을 하고, 공부하고, 팟캐스트를 듣고, 일본인 친구를 사귀어도
**"내 일본어가 어디가 어떻게 틀렸고 무엇이 적절한지를 화용론적으로, 언어 교사처럼 알려주는 사람이 없다."**
그 공백을 채우는 서비스.

## 점검 결과

### 맞게 가고 있는 것
- **끌려가지 않기**(ADR 0002, 0009): "뜻이 통하니 아무도 지적하지 않는다"는 문제를 코드 검증으로 정면에서 다룬다.
- **장면**(매체·상대)을 과제와 판정의 기준으로 둔 것, 표현 모드, 직역 간섭 플래그 (ADR 0004).
- **교사의 순환**: 틀린 자리만 알려 주고 스스로 고치게 하기, 약점을 다시 만나게 하기 (ADR 0013).
- **개인 코퍼스**: 오타와 오개념을 가르고, 반복되는 패턴만 약점으로 본다 (ADR 0010).

### 어긋난 것 (무게중심이 옮겨 갔다)
1. **화용이 아니라 문법 쪽으로 기울었다.** 검증 장치(인용 위치, 합침 검출, 변환 실수)는 대부분 형태 오류를 위한 것이고,
   실험에서도 문법 모드는 위치 탐지 1.00, 표현 모드는 0.74~0.93 이다. 프로젝트 이름(Pragmatics)과 최초 기획이 가리키는 쪽이 가장 약하고 가장 덜 검증됐다.
2. **"내 일본어"가 아직 들어오지 않는다.** 지금 입력은 앱이 낸 과제와 한국어 문장 번역이다. 둘 다 연습이지,
   사용자가 오늘 실제로 쓰거나 말한 일본어가 아니다. 최초 기획의 공백은 후자에 있다. 번역은 한국어 직역 간섭을 과하게 끌어내는 대리 지표이기도 하다.
   (ADR 0010 논의에서 "자유 입력"을 제안했지만 구현된 것은 번역 모드였다.) 회사 문장은 PII 게이트가 선행 조건이다.
3. **교사처럼 "왜, 그리고 상대가 바뀌면 어떻게"를 설명하지 않는다.** 지금은 지적 하나에 해설 1~2문장, 장면 하나에 자연스러운 문장 하나다.
   화용의 핵심은 대비다: 같은 말을 상사·동료·친구에게 각각 어떻게 하는가. 이 대비가 없다.
4. **말하기가 빠져 있다.** 최초 문제 제기의 절반(음성 인식이 틀린 조사를 맞게 바꿔 버린다)은 범위 밖으로 남아 있다.
5. **해설의 정확성이 검증되지 않았다.** 틀릴 수 있는 교사다. '지적이 틀림' 판정과 원어민 검수(ADR 0007)가 그 장치지만 아직 데이터가 없다.
6. **실사용 기록이 0건이다** (2026-10-03 기준 `data/` 가 비어 있다). 학습 순환·코퍼스·추이·백업을 모두 만들었지만 실제로 돌려 본 적이 없다.
   지금 가장 큰 위험은 기능 부족이 아니라, 쓰지 않은 채로 기능이 계속 늘어나는 것이다.

## 모바일 UI + Firebase 배포를 CI/CD 에 넣는 안

### 모바일은 최초 기획과 맞는다
"실제로 쓴 일본어"는 회사와 이동 중에 생긴다. PC 앞에 앉아야만 쓸 수 있으면 2번(내 일본어가 들어오지 않는다)이 풀리지 않는다.

### 그러나 Firebase 배포는 지금 구조와 맞지 않는다
| 걸리는 점 | 내용 |
|---|---|
| 실행 환경 | Firebase Hosting 은 정적 파일용이다. Streamlit(파이썬 서버, SudachiPy)은 올릴 수 없다 → Cloud Run 컨테이너 + Hosting 연결, 또는 화면을 웹앱으로 다시 만들고 API 를 분리 |
| 저장 | 지금은 로컬 JSONL. 서버에 올리면 Firestore 등으로 옮겨야 한다 (`store.py` 가 교체 지점) |
| 로그인 | 공개 주소가 되면 인증이 필수다. 인증 없이는 누구나 내 API 키로 채점을 돌릴 수 있다. 로그인은 범위 밖이었다 |
| 개인정보 | 내가 쓴 글이 PC 밖 저장소에 놓인다. PII 게이트가 아직 연계되지 않았다 |
| 비용 | 채점 1번 약 $0.04 + 서버 비용. 예산 상한과 호출 제한이 필요하다 |
| CI/CD | 지금은 CI 자체가 없다. 테스트 자동 실행이 먼저다 |

### 버린 것은 아니고 순서의 문제
배포의 선행 조건: (a) 실사용으로 쓸 만하다는 확인, (b) PII 게이트, (c) 인증·저장·예산 설계.

## 제안하는 순서
1. **지금 (무료, 반나절)**
   - GitHub Actions 로 push 마다 테스트 실행 (CI 의 첫 단계. 배포는 없음).
   - 폰에서 쓰기: PC 에서 앱을 띄우고 같은 Wi-Fi(또는 Tailscale 같은 사설망)에서 폰 브라우저로 접속. 배포·로그인·저장소 이전 없이 모바일 사용이 된다.
   - 폰 화면에 맞게 화면 정리 (사이드바에 있는 모드·입력 방식을 본문으로).
2. **최초 기획으로 되돌리는 기능 (API 비용 소액)**
   - "내가 실제로 쓴 일본어" 입력: 일본어를 붙여 넣고 장면만 고른다. 개인 대화부터, 회사 문장은 PII 게이트 이후.
   - "상대가 바뀌면": 같은 뜻을 상사·동료·친구에게 어떻게 말하는지 나란히 보여주고 차이를 설명 (화용의 대비).
3. **2~4주 실사용 후**: 원어민 검수, 보류한 유료 재실험, 그리고 배포 여부 재검토.
   배포한다면 Cloud Run + Firebase Hosting + 인증(본인 한 명 허용) + Firestore + 예산 상한, CD 는 테스트 통과 후 main 에서.

## 결과
- 이 ADR 은 결정이 아니라 점검 기록이다. 사용자가 순서를 고르면 해당 ADR 을 새로 쓴다.
