# 0010. 개인 학습자 코퍼스: 빈출 오답, 오타 거르기, 사용자 판정

- 상태: 채택 (2026-09-29)

## 맥락
도메인 관점에서 점검해 보니, 이 앱은 "지적하고 끝"이라 학습 도구로는 프로토타입 수준이었다.
- 상위 5개가 "조사" 같은 **유형** 단위라 거칠다. 실제로 반복되는 것은 "`会う` 앞에 を" 같은 **구체적 패턴**이다.
- 오타와 오개념이 섞여 순위에 오른다. 한 번 한 오타가 "내 약점"으로 잡히면 도구를 믿을 수 없게 된다.
- 입력이 LLM 이 만든 과제뿐이라, 쌓이는 데이터가 인위적이다.

사용자는 사전 없이 한국어 문장을 일본어로 옮기는 연습을 자주 해서 **개인 학습자 코퍼스**(학습자가 쓴 글에 오류 주석을 붙여 모은 것)를 쌓고 싶어 한다.

## 결정
1. **입력 방식 두 가지**: 앱이 낸 과제 / 내가 가져온 한국어 문장. 한국어 원문과 걸린 시간을 기록한다 (스키마 s3).
2. **사용자 판정 4종** (사용자 선택): 실수(오타·변환) / 몰랐음 / 애매 / 지적이 틀림.
   `data/labels.jsonl` 에 한 줄씩 **추가만** 한다. 시도 기록은 고치지 않는다. 같은 태그를 다시 판정하면 마지막 것이 이기고, 선택 해제는 취소.
   태그는 `시도id:시작:끝:유형` 키로 가리킨다.
3. **빈출 오답 = 패턴 단위** (`coach/corpus.py`, LLM 없음). 키 = (유형, 바뀐 기본형 → 기본형, 걸리는 말).
   - 활용을 없앤다: `合って→会って` → `合う → 会う`. 음편 변이형도 맞춘다 (`飲んで`의 で → て, `飲んだ`의 だ → た).
   - 조사만 바뀌었으면 원문에서 그 뒤의 첫 내용어를 붙인다: `を → に (会う)`. 조사 오류는 "무엇에 걸리는가"까지 봐야 의미가 있다.
   - **서로 다른 시도에서 2번 이상** 나온 패턴만 빈출 오답이다.
4. **오타 거르기 세 겹**:
   - ① 변환 실수 후보: 수정 전후의 **읽기가 같으면** (`合って/会って`, `効く/聞く`) IME 변환 실수로 보고 뺀다. 형태소 분석기로 확인한 결과 확실히 잡힌다.
   - ② 반복성: 한 번뿐인 오류는 빈출 오답에 오르지 않는다.
   - ③ 사용자 판정이 최종.
5. **기본 집계** (사용자 선택): 판정하지 않은 태그도 넣되, '실수'·'지적이 틀림' 판정과 변환 실수 후보는 뺀다.
   변환 실수 후보라도 '몰랐음'으로 판정하면 센다. '몰랐음만 보기' 필터를 둔다. 유형 상위 5개에도 같은 제외를 적용한다.

## 버린 대안
- **LLM 에게 오타인지 판단시키기**: 원칙 위반(판단은 코드와 사람). 모델의 추측으로 순위가 바뀌면 안 된다.
- **사전에 없는 말(미등록어)로 오타 판별**: 확인해 보니 형태소 분석기가 오타도 아는 단어 조각으로 쪼개서 신호가 나오지 않았다.
- **'몰랐음'만 세기**: 가장 깨끗하지만 태그마다 판정해야 순위가 생긴다. 매일 쓰기에 부담.

## 한계
- **가나 한 글자 오타**(`ありがと ございます`)는 조사 오류(`を→に`)와 똑같이 한 글자 차이라 코드로 구별할 수 없다 → ②·③에 맡긴다.
- 조사의 "걸리는 말"은 원문에서 찾으므로, 그 동사가 틀리게 쓰였으면(`合う`) 틀린 쪽 기본형이 키에 들어간다.
- 변환 실수 후보를 기본으로 빼므로, 정말 한자를 몰라서 틀린 경우는 '몰랐음'을 눌러야 잡힌다.
- 번역 과제는 자유 작문보다 한국어 직역 간섭이 많이 나온다.

## 연결
- '지적이 틀림' 판정은 도구의 **정밀도**를 재는 재료이고, 평가 세트 후보가 된다 (ADR 0007 을 일회성이 아니라 쓰면서 쌓이는 구조로).
- PII 게이트(사용자가 별도로 만드는 중)와 나중에 캐스케이드로 연계한다. 그때 "원문은 로컬에만, 채점·인용 검증은 가린 문장 기준" 같은 규칙을 새 ADR 로 정한다 (원칙 A·D 와 충돌하지 않게).
