# 인수인계 (세션 간)

새 세션이 시작되면 SessionStart 훅(`tools/session_handoff.py`)이 이 문서를 자동으로 읽어 들인다.
원칙·구조·명령은 `CLAUDE.md`, 결정의 이유는 `docs/adr/` 에 있다. 여기에는 **지금 멈춘 지점과, 문서만 봐서는 알 수 없는 것**만 적는다.
세션을 끝내기 전에 이 문서를 갱신한다 (특히 1·2·6번).

마지막 갱신: 2026-10-07

## 1. 지금 멈춘 지점 — 새 세션은 여기서 시작한다

**사용자의 답을 기다리는 질문이 하나 있다.**
사용자가 2026-10-03 에 말했다: "아직 개발은 더 진행해야겠네요. 실사용하기엔 내가 원하는 기능이 덜 갖춰졌습니다."
그래서 "어떤 기능이 부족한가"를 물었고, 아직 답을 받지 못했다. 추측으로 만들지 말고 **답을 먼저 듣는다.**

내가 후보로 제시한 두 가지 (ADR 0015 의 2단계, 최초 기획으로 되돌리는 기능):
- **실제로 쓴 일본어 넣기**: 일본어를 붙여 넣고 장면(매체·상대)만 고르면 채점. 지금은 과제와 한국어 번역만 된다.
- **상대가 바뀌면 어떻게**: 같은 뜻을 상사·동료·친구에게 각각 어떻게 말하는지 나란히 보여주고 차이를 설명 (화용의 대비).

새 세션의 첫 응답에서 할 일:
1. 이 인수인계를 읽었다고 한두 문장으로 알린다 (길게 요약하지 않는다).
2. 사용자의 첫 메시지가 다른 요청이면 그것을 먼저 한다.
3. 그렇지 않으면 위 질문("무엇이 부족한가")부터 이어간다.

## 2. 저장소 상태

- 브랜치 `main`, 원격은 GitHub `fairyofdata/PragmaticsKR2JP`. 정확한 상태는 훅이 이 문서 아래에 붙여 주는 "지금의 저장소 상태"를 본다 (마지막 커밋, 커밋·푸시 안 된 것).
- 테스트 53개 통과 (`pytest`). GitHub Actions(`tests.yml`)는 `0c92152` 에서 통과를 확인했다.
- 버전: 유형표 v1, 채점 프롬프트 p2, 스키마 s4, 채점 모델 `gpt-5.6-terra`, 출제 `gpt-5.6-luna`.
- **실사용 기록은 0건이다** (`data/` 가 비어 있다). 시연 예시 12건(`samples/`)은 프롬프트 p1 로 만든 것이라 요약 탭에서 "이전 버전 기록도 포함"을 켜야 보인다.

## 4. 보류 중 (사용자 결정: 비용 드는 것은 나중에 한 번에)

임시 평가 세트·시연 예시를 실제 번역으로 교체할 때 함께 한다.
- p2 실험 재실행 (`experiments.repro`, 약 $1.3). README 의 실험 표는 p1 기준이다. p0·p1 결과 파일에는 모델 원래 응답이 없어 `--rescore` 가 안 된다.
- 시연 예시 재생성 (`experiments.build_samples`, 약 $0.3).
- 연습 화면 스크린샷 `practice.png` (API 필요, 약 $0.04). 지금 것은 예전 화면이다.
- README 의 비용 표: 채점 1번이 p1 기준 약 $0.02 로 적혀 있다. p2 실측은 약 $0.04.
- 평가 세트를 사용자의 실제 번역으로 다시 만들기 (ADR 0007). 사용자가 글을 가져와야 시작한다.
- Firebase 배포: 실사용 확인, PII 게이트, 인증·저장·예산 설계가 먼저다 (ADR 0015).

## 5. 사용자가 직접 해야 하는 것 / 아직 확인되지 않은 것

- 폰에서 쓰려면 `.env` 에 `COACH_PASSCODE=<8자 이상>` 을 직접 넣어야 한다 (키·암호는 내가 넣지 않는다).
- **실제 폰에서 접속해 본 적이 없다.** 폰 크기 화면은 자동 브라우저로, 암호 잠금은 테스트로만 확인했다.
- 백업 "내려받기" 버튼은 자동 테스트로 누를 수 없었다. 버튼이 호출하는 함수만 확인했다.
- 고쳐 쓰기의 "다시 채점"은 실제 API 로 돌려 본 적이 없다 (채점 경로 자체는 p2 로 1회 확인).
- GitHub 저장소의 설명(description)과 토픽이 비어 있다. 웹 설정이라 사용자가 직접.
- PII 게이트는 사용자가 따로 만드는 중이다. 지난 세션에 `cascadedlp` 라는 MCP 서버가 연결 실패로 떠 있었다 (그 게이트일 수 있다).

## 6. 이 사용자와 일하는 방식 (대화에서 확인된 것)

- 대화는 한국어. 코드는 읽을 수 있지만 쓰는 건 약하다 → 새 개념은 한 줄로 풀어 쓴다.
- **큰 설계 결정은 먼저 묻는다.** 선택지 2~4개와 추천안을 함께 주면 빨리 정해진다 (AskUserQuestion 이 잘 맞았다). 지금까지 대부분 추천안을 골랐지만, 그렇다고 묻지 않고 진행하지는 않는다.
- **주요 변경은 지시가 없어도 ADR 로 남긴다** (상시 지시, 2026-09-30). ADR 을 쓰면 색인과 CLAUDE.md "현재 상태"도 갱신한다.
- 커밋·푸시는 요청받았을 때 한다. "커밋해 주세요"는 커밋만이다. 비용이 드는 API 호출은 금액을 먼저 말한다.
- 사용자는 편향·과적합·범용성에 민감하다. 예시 하나에 맞춘 규칙을 싫어한다. 한계와 틀린 점을 숨기지 않고 말하는 것을 좋아한다.
- 결과 보고는 자세히 원한다. 다만 확인하지 못한 것은 확인하지 못했다고 적는다.
- 최초 기획: "내 일본어가 어디가 틀렸고 무엇이 적절한지 화용론적으로, 교사처럼 알려주는 사람이 없다." 새 기능을 제안할 때 이 공백을 줄이는지 먼저 본다.

## 7. 이 환경에서 걸렸던 것 (같은 실수를 반복하지 않기 위해)

- 셸은 Windows PowerShell 5.1 이다. `&&` 가 없고, 작은따옴표 문자열에서는 `` `n `` 이 줄바꿈으로 바뀌지 않는다.
- **커밋 메시지에 큰따옴표가 있으면 git 으로 넘어가다 깨진다** (오류도 안 보이고 커밋만 안 된다). 메시지를 파일에 쓰고 `git commit -F <파일>` 로 한다.
- PowerShell 로 문서를 치환하면 백틱이 사라진 적이 있다. **문서 여러 개를 고칠 때는 작업 폴더(scratchpad)에 파이썬 스크립트를 쓰고**, 바꿀 문장이 있는지 `assert` 로 확인한 뒤 치환한다.
- `Remove-Item` 으로 임시 폴더를 지우려다 명령 전체가 막힌 적이 있다. 임시 파일은 세션 작업 폴더에 두고 지우지 않는다.
- 화면을 테스트 도구(AppTest)로 눌러 볼 때는 **`COACH_DATA_FILE` 을 임시 경로로 돌린다.** 안 그러면 실제 `data/` 에 기록이 들어간다 (한 번 들어가서 지웠다). pytest 안에서는 `monkeypatch.setattr(store, "DATA_FILE", ...)`.
- 셸 안전 검사가 일시적으로 응답하지 않을 때가 있다. 연속으로 재시도하지 말고 읽기 전용 작업을 먼저 한다. `.git/refs/` 를 직접 읽으면 커밋 상태를 알 수 있다.
- `gh` CLI 가 없다. CI 결과는 `curl https://api.github.com/repos/fairyofdata/PragmaticsKR2JP/actions/runs?per_page=1` 로 본다.
- Streamlit 화면을 고칠 때는 `developing-with-streamlit` 스킬을 먼저 읽고, 위젯 사용법은 `streamlit docs st.<이름>` 으로 확인한다.
- 내장 브라우저에서는 GitHub 의 이미지가 로드되지 않았다 (실제로는 정상). 이미지 확인은 `curl -sI` 로 한다.
- Streamlit 은 주소를 지정하지 않으면 모든 네트워크에 열린다. `.streamlit/config.toml` 의 `address = "localhost"` 를 지우지 않는다.

